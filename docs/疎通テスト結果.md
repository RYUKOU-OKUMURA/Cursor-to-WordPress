## 2. エラーパターンと対処法

### 2-1. 401エラー（認証失敗）

**症状**:
```
エラー [401]: 認証に失敗しました
```

**原因**:
- ユーザー名が間違っている
- Application Passwordが間違っている
- Application Passwordsが無効化されている

**対処法**:
1. `.env`ファイルの`WP_USER`が正しいか確認
2. `.env`ファイルの`WP_APP_PASSWORD`が正しいか確認
   - スペース区切りのままコピーする（例: `xxxx xxxx xxxx xxxx xxxx xxxx`）
   - 前後に余計なスペースや改行がないか確認
3. WordPress管理画面で Application Passwords が有効か確認
   - 「ユーザー」→「プロフィール」→「アプリケーションパスワード」セクションがあるか
4. パスワードを再発行して試す

**確認コマンド**:
```bash
# 環境変数の確認
cat .env

# 直接APIをテスト
curl -u "username:application_password" \
  https://your-site.com/wp-json/wp/v2/users/me
```

---

### 2-2. 403エラー（権限不足）

**症状**:
```
エラー [403]: 権限が不足しています
```

**原因**:
- ユーザーに投稿権限がない
- REST APIへのアクセスが制限されている

**対処法**:
1. WordPress管理画面でユーザーの権限を確認
   - 「投稿者」以上の権限が必要
   - 「購読者」「寄稿者」では投稿APIが使用不可
2. セキュリティプラグインがREST APIをブロックしていないか確認
   - Wordfence, iThemes Security等
3. サーバー側の設定（.htaccess等）でAPIがブロックされていないか確認

**確認コマンド**:
```bash
# ユーザー権限の確認
curl -u "username:application_password" \
  https://your-site.com/wp-json/wp/v2/users/me | jq '.roles'
```

---

### 2-3. 404エラー（エンドポイント不正）

**症状**:
```
エラー [404]: エンドポイントが見つかりません
```

**原因**:
- `WP_URL`が間違っている
- パーマリンク設定が「基本」になっている
- REST APIが無効化されている

**対処法**:
1. `.env`ファイルの`WP_URL`を確認
   - 末尾にスラッシュがないこと（`https://your-site.com`）
   - `https://`から始まっていること
   - サブディレクトリの場合は含める（`https://your-site.com/blog`）
2. パーマリンク設定を確認
   - WordPress管理画面「設定」→「パーマリンク」
   - 「基本」以外（投稿名など）に設定
3. REST APIが有効か確認

**確認コマンド**:
```bash
# REST APIのルートにアクセス
curl https://your-site.com/wp-json/

# 投稿エンドポイントの存在確認
curl https://your-site.com/wp-json/wp/v2/posts
```

### 2-4. 500エラー（サーバーエラー）

**症状**:
```
エラー [500]: サーバーエラーが発生しました
```

**原因**:
- サーバー側でエラーが発生
- PHPのメモリ不足
- プラグインの競合

**対処法**:
1. WordPressのエラーログを確認
   - `wp-content/debug.log`（デバッグモードが有効な場合）
2. サーバーのエラーログを確認
3. プラグインを一時的に無効化して切り分け
4. テーマを一時的にデフォルトに切り替えて確認

---

### 2-5. 接続エラー

**症状**:
```
接続エラーが発生しました
```

**原因**:
- サイトがダウンしている
- ネットワーク接続の問題
- DNSの問題
- SSL証明書の問題

**対処法**:
1. ブラウザでサイトにアクセスできるか確認
2. ネットワーク接続を確認
3. VPNやプロキシを使用している場合は無効化して試す
4. SSL証明書が有効か確認

**確認コマンド**:
```bash
# サイトへの接続確認
curl -I https://your-site.com

# DNS解決の確認
nslookup your-site.com

# SSL証明書の確認
openssl s_client -connect your-site.com:443
```

## 3. デバッグ方法

### 3-1. 詳細ログの出力

```bash
python post_to_wp.py articles/sample_article.md -v
```

`-v`（`--verbose`）オプションで詳細なログが出力されます。

### 3-2. 環境変数の確認

```python
from dotenv import load_dotenv
import os

load_dotenv()
print(f"WP_URL: {os.getenv('WP_URL')}")
print(f"WP_USER: {os.getenv('WP_USER')}")
print(f"WP_APP_PASSWORD: {'*' * len(os.getenv('WP_APP_PASSWORD', ''))}")
```

### 3-3. 直接APIテスト

```python
import requests
from requests.auth import HTTPBasicAuth

response = requests.post(
    "https://your-site.com/wp-json/wp/v2/posts",
    auth=HTTPBasicAuth("username", "application_password"),
    json={"title": "テスト投稿", "content": "テスト", "status": "draft"},
    timeout=30
)
print(f"Status: {response.status_code}")
print(f"Response: {response.json()}")
```

## 4. よくある問題と解決策

### Q: スペース入りのパスワードはそのまま入力？
**A**: はい、そのまま入力してください。
```
WP_APP_PASSWORD=xxxx xxxx xxxx xxxx xxxx xxxx
```

### Q: HTTPサイトでも使える？
**A**: 技術的には可能ですが、セキュリティ上推奨しません。警告メッセージが表示されます。

### Q: マルチサイトでも使える？
**A**: はい。サブサイトのURLを`WP_URL`に指定してください。

### Q: 日本語タイトルは使える？
**A**: はい。UTF-8でエンコードされて送信されます。
