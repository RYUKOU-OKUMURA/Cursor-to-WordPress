### 2.2 requests（HTTP通信）

**選定理由**
- PythonでHTTP通信を行う事実上の標準ライブラリ
- シンプルなAPI設計（1行でPOSTリクエストが書ける）
- Basic認証のサポートが組み込み
- エラーハンドリングが容易

**インストール**
```bash
pip install requests
```

**使用例**
```python
import requests
from requests.auth import HTTPBasicAuth

response = requests.post(
    url="https://example.com/wp-json/wp/v2/posts",
    json={"title": "タイトル", "content": "本文", "status": "draft"},
    auth=HTTPBasicAuth("username", "app_password")
)
```

**主要機能**
| 機能 | メソッド/属性 |
|------|---------------|
| POSTリクエスト | `requests.post()` |
| Basic認証 | `HTTPBasicAuth` |
| JSON送信 | `json=` パラメータ |
| レスポンス取得 | `response.json()` |
| ステータスコード | `response.status_code` |
| エラー発生時に例外 | `response.raise_for_status()` |

### 2.3 markdown2（Markdown変換）

**選定理由**
- 軽量で依存関係が少ない
- 日本語を含むMarkdownの変換が安定
- 拡張機能（extras）でカスタマイズ可能
- mistune より設定がシンプル

**インストール**
```bash
pip install markdown2
```

**使用例**
```python
import markdown2

html = markdown2.markdown(
    markdown_text,
    extras=["fenced-code-blocks", "tables", "strike"]
)
```

**有効化する拡張機能（extras）**

| extra名 | 機能 | 例 |
|---------|------|-----|
| `fenced-code-blocks` | コードブロック | \`\`\`python ... \`\`\` |
| `tables` | テーブル | `| a | b |` |
| `strike` | 打ち消し線 | `~~text~~` |

**変換例**
```
入力（Markdown）:
## 見出し
これは**太字**です。

出力（HTML）:
<h2>見出し</h2>
<p>これは<strong>太字</strong>です。</p>
```

### 2.4 python-dotenv（環境変数管理）

**選定理由**
- パスワードをコードに直書きしないためのセキュリティ対策
- `.env`ファイルを読み込んで環境変数として使用
- シンプルで設定が簡単

**インストール**
```bash
pip install python-dotenv
```

**使用例**

`.env`ファイル:
```
WP_URL=https://example.com
WP_USER=your_username
WP_APP_PASSWORD=xxxx xxxx xxxx xxxx xxxx xxxx
```

Pythonコード:
```python
import os
from dotenv import load_dotenv

# .envファイルを読み込み
load_dotenv()

# 環境変数を取得
wp_url = os.getenv("WP_URL")
wp_user = os.getenv("WP_USER")
wp_password = os.getenv("WP_APP_PASSWORD")
```

### 2.5 argparse（コマンドライン引数）

**選定理由**
- Python標準ライブラリ（追加インストール不要）
- `--help`オプションを自動生成
- 引数のバリデーションが容易

**使用例**
```python
import argparse

parser = argparse.ArgumentParser(
    description="MarkdownファイルをWordPressに投稿するツール"
)
parser.add_argument(
    "file",
    help="投稿するMarkdownファイルのパス"
)
parser.add_argument(
    "--publish",
    action="store_true",
    help="公開状態で投稿（デフォルトは下書き）"
)

args = parser.parse_args()

# args.file → ファイルパス
# args.publish → True/False
```

**生成されるヘルプ**
```
$ python post_to_wp.py --help
usage: post_to_wp.py [-h] [--publish] file

MarkdownファイルをWordPressに投稿するツール

positional arguments:
  file        投稿するMarkdownファイルのパス

optional arguments:
  -h, --help  show this help message and exit
  --publish   公開状態で投稿（デフォルトは下書き）
```

### 2.6 WordPress REST API

**選定理由**
- WordPress標準機能（プラグイン不要）
- WordPress 5.6以上で標準搭載
- 安定性が高く、ドキュメントが充実

**エンドポイント**
```
ベースURL: {サイトURL}/wp-json/wp/v2/

投稿:
POST /posts          新規作成
GET  /posts          一覧取得
GET  /posts/{id}     単一取得
PUT  /posts/{id}     更新
DELETE /posts/{id}   削除

メディア（Phase 3で使用）:
POST /media          画像アップロード
```

**リクエスト形式**
```
Content-Type: application/json
Authorization: Basic {base64エンコードされた認証情報}
```

**投稿で使用するフィールド**

| フィールド | 型 | 説明 |
|-----------|------|------|
| `title` | string | 記事タイトル |
| `content` | string | 本文（HTML） |
| `status` | string | `draft`, `publish`, `pending`, `private` |
| `categories` | array | カテゴリーIDの配列（Phase 2） |
| `tags` | array | タグIDの配列（Phase 2） |
| `featured_media` | integer | アイキャッチ画像ID（Phase 3） |

### 2.7 Application Passwords（認証）

**選定理由**
- WordPress 5.6で標準搭載（プラグイン不要）
- OAuth より設定がシンプル
- アプリごとにパスワードを発行・取り消しできる
- 本体パスワードを直接使わないのでセキュリティ的に安全

**設定手順**

1. WordPress管理画面にログイン
2. **ユーザー** → **プロフィール** に移動
3. ページ下部の「**アプリケーションパスワード**」セクションを探す
4. 「新しいアプリケーションパスワード名」に任意の名前を入力
   - 例: `Cursor自動投稿`
5. 「**新しいアプリケーションパスワードを追加**」をクリック
6. 表示されたパスワード（スペース区切り）をコピーして`.env`に保存

**パスワード形式**
```
xxxx xxxx xxxx xxxx xxxx xxxx
（スペース区切り24文字）
```

**注意**: このパスワードは一度しか表示されません。必ずコピーして保存してください。

**認証方式（Basic認証）**
```
Authorization: Basic {base64(username:app_password)}
```

## 4. 開発環境セットアップ

### 4.1 初回セットアップ手順

```bash
# 1. プロジェクトフォルダに移動
cd /path/to/Cursor-to-WordPress

# 2. （推奨）仮想環境を作成
python3 -m venv venv

# 3. 仮想環境を有効化（Mac/Linux）

# 4. 依存関係をインストール
pip install -r requirements.txt

# 5. .envファイルを作成
cp .env.example .env

# 6. .envを編集して認証情報を設定
```

```bash
# WordPress サイトURL（末尾のスラッシュなし）

WP_USER=your_username

# アプリケーションパスワード（WordPress管理画面で発行）
WP_APP_PASSWORD=xxxx xxxx xxxx xxxx xxxx xxxx
```

## 6. トラブルシューティング

### 6.1 よくあるエラーと対処

| エラー | 原因 | 対処 |
|--------|------|------|
| `ModuleNotFoundError: No module named 'requests'` | ライブラリ未インストール | `pip install requests` |
| `FileNotFoundError: .env` | .envファイルがない | `.env.example`をコピーして作成 |
| `401 Unauthorized` | 認証失敗 | ユーザー名とアプリパスワードを確認 |
| `403 Forbidden` | 権限不足 | ユーザーの投稿権限を確認 |
| `404 Not Found` | URLが間違っている | WP_URLを確認（末尾スラッシュなし） |
| `Connection Error` | ネットワーク問題 | インターネット接続を確認 |

### 6.2 REST API有効化の確認

ブラウザで以下のURLにアクセス:
```
https://あなたのサイト/wp-json/
```

JSONが表示されればREST APIは有効です。
