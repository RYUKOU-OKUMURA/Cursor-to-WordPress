## 4. API設計

### 4.1 WordPress REST API エンドポイント

**投稿作成**
```
POST {WP_URL}/wp-json/wp/v2/posts
```

**リクエストヘッダー**
```
Content-Type: application/json
Authorization: Basic {base64(username:password)}
```

**リクエストボディ**
```json
{
  "title": "記事タイトル",
  "content": "<p>HTML本文</p>",
  "status": "draft"
}
```

**レスポンス（成功時: 201 Created）**
```json
{
  "id": 123,
  "link": "https://example.com/article-slug/",
  "status": "draft",
  "title": {
    "rendered": "記事タイトル"
  },
  "_links": {
    "self": [{"href": "https://example.com/wp-json/wp/v2/posts/123"}]
  }
}
```

**編集画面URL（自動生成）**
```
{WP_URL}/wp-admin/post.php?post={id}&action=edit
```

### 4.2 エラーレスポンス

| ステータス | 意味 | 対処 |
|-----------|------|------|
| 401 | 認証失敗 | ユーザー名・パスワードを確認 |
| 403 | 権限不足 | ユーザーの投稿権限を確認 |
| 404 | エンドポイント未発見 | URLとREST API有効化を確認 |
| 500 | サーバーエラー | WordPress側のログを確認 |

## 6. エラーハンドリング設計

### 6.1 エラー分類と対応

```
エラー発生
    │
    ├─▶ 設定エラー（load_config）
    │     ├─ .envファイルが存在しない
    │     └─ 必須項目が未設定
    │
    ├─▶ ファイルエラー（read_markdown_file）
    │     ├─ ファイルが存在しない
    │     └─ 読み込み権限がない
    │
    ├─▶ 変換エラー（convert_markdown_to_html）
    │     └─ 不正なMarkdown形式（通常は発生しない）
    │
    └─▶ APIエラー（post_to_wordpress）
          ├─ ネットワーク接続エラー
          ├─ 認証エラー（401）
          ├─ 権限エラー（403）
          └─ サーバーエラー（5xx）
```

### 6.2 エラーメッセージ形式

```
[エラー] カテゴリ: 詳細メッセージ

例:
[エラー] ファイル: 'article.md' が見つかりません
[エラー] 認証: ユーザー名またはパスワードが正しくありません
[エラー] 接続: WordPressサーバーに接続できません
```

## 8. 設計原則

| 原則 | 説明 | 適用 |
|------|------|------|
| **KISS** | Keep It Simple, Stupid | 単一ファイル構成、最小限の依存関係 |
| **YAGNI** | You Ain't Gonna Need It | Phase 1では必要な機能のみ実装 |
| **関心の分離** | 機能ごとに関数を分ける | 読み込み、変換、API通信を分離 |
| **早期リターン** | エラー時は早めに終了 | 各関数でバリデーション後に処理 |
| **設定の外部化** | 機密情報はコード外 | .envファイルで管理 |
